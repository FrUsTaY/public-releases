## 🔴 Критично

### A1. Статичные шкалы навыков объявлены как `progressbar`
`index.html:1627, 1636, 1645, 1654, 1663` · CSS `1009–1023`

```html
<div class="skill-bar" role="progressbar" aria-valuenow="95" aria-valuemin="0" aria-valuemax="100" ...>
    <div class="skill-fill" style="width: 95%;"></div>
</div>
```

По спецификации ARIA `progressbar` описывает **изменяющееся** состояние заполнения; AT периодически опрашивает `aria-valuenow`. Здесь значение жёстко прописано в разметке, а анимация делается через `transform: scaleX(0 → 1)` при появлении секции (CSS 1016–1023, JS 2008–2021). Итог: скринридер объявит «95%» сразу, визуально полоса доедет до 95% через 1.5 с, и ни одного обновления состояния не произойдёт. Для неизменяемого процента это декоративная полоса.

**Исправление:** заменить `role="progressbar"` + `aria-valuenow/min/max` на `role="img" aria-label="Backend Development: 95%"`. Оставить progressbar только если решите реально анимировать `aria-valuenow` из JS.

### J1. Konami-пасхалка слушает клавиатуру поверх формы
`index.html:2128–2135` · рядом: `2183–2196` (1337), `2488–2499` (doh/homer)

```js
document.addEventListener('keydown', function(e) {
    konamiCode.push(e.key);
    konamiCode = konamiCode.slice(-10);
    if (konamiCode.join('').toLowerCase() === konamiPattern.join('').toLowerCase()) { ... }
});
```

В отличие от обработчиков `1337` и `doh`, здесь **нет проверки активного элемента**. Пользователь, печатающий в поле «Тема проекта» или в `<textarea>` текст со стрелками и буквами `b`/`a` (например, `ba`… `arrowup` невозможно ввести, но `b`,`a` и стрелки навигации по тексту — вполне), получит Konami-режим прямо во время ввода. Плюс три независимых обработчика `keydown` на `document` обрабатывают каждое нажатие по три раза.

**Исправление:** общая функция `isTypingTarget(el)` (`INPUT`/`TEXTAREA`/`SELECT`/`[contenteditable]`) в начале каждого обработчика, либо один централизованный keydown-роутер. Заодно убрать мёртвую проверку `classList.contains('form-group')` в обработчике 1337 (2186) — класс `form-group` стоит на `div`-обёртке (1720), а не на `input`.

## 🟠 Важно

### A2. Пункт «УЗНАТЬ БОЛЬШЕ» ведёт в раздел, которого нет в навигации
`index.html:1405` · JS `2042–2058` · CSS `1285–1300`

Кнопка скроллит к `#about`, но в `nav-links` раздела «О компании» нет (УСЛУГИ / ПОРТФОЛИО / ТАРИФЫ / НАВЫКИ / КОНТАКТЫ) — пользователь попадает в секцию, из которой нельзя вернуться к списку разделов через меню. Заодно бренд пишется в трёх вариантах: `NEXUS CODE` (title/OG, 6–17), `NEXUS_CODE` (logo 1372, footer 1743), `NEXUS_CODE SYSTEM` (console.log 2517) — для узнаваемости и сниппета стоит остановиться на одном.

### A3. Значение навыка озвучивается дважды
`index.html:1625–1628` (и аналогично 1634, 1643, 1652, 1661)

```html
<span aria-label="Уровень: 95 процентов">95%</span>   <!-- внутри .skill-label -->
...
<div class="skill-bar" role="progressbar" aria-label="Навык Backend Development: 95%">
```

`aria-label` на `span` без роли игнорируется большинством AT, при этом видимый текст «95%» читается, плюс `aria-label` соседней полосы содержит то же число. Двойное объявление. Достаточно удалить `aria-label` у span'ов.

### A4. Мобильное меню: `aria-controls` на скрытом блоке, нет Esc, фокус теряется при ресайзе
`index.html:1373` · CSS `1285–1300` · JS `2325–2342`

При ≤768 px `#navLinks` имеет `display:none`; переключение корректно меняет `aria-expanded` (2331, 2340), но: (а) нет `aria-haspopup="true"`; (б) если меню открыто и пользователь расширит окно, ссылки остаются в DOM, но становятся недостижимыми — фокус «проваливается» в никуда; (в) закрытие меню по Esc не реализовано. Нужен `resize`-сброс состояния и Esc-обработчик.

### A5. Ловушка фокуса в модалке не покрывает уход фокуса наружу
`index.html:1963–1978`

Обрабатываются только два перехода: Shift+Tab от первого → последний и Tab от последнего → первый. Если `document.activeElement` оказался вне диалога (клик по затемнённой области мимо `.modal-content` не попадает в обработчик закрытия на 1958–1962, либо AT увёл фокус), Tab продолжает обход страницы под оверлеем. Надёжнее: при `!modal.contains(document.activeElement)` возвращать фокус на первый фокусируемый элемент диалога.

### A6. Английские вставки без `lang="en"`
`index.html:2162` («You are now a true hacker!»), `2274–2284` (Red/Blue Pill), `2198` (1337-алерт). Внутри `lang="ru"` они будут прочитаны с русским произношением. Для DOM-сообщений (2162) — обернуть в `<span lang="en">`; нативные `alert` это не лечится (см. J2).

### J2. Блокирующие `confirm()`/`alert()` в пасхалках
`index.html:2198, 2268, 2274, 2280, 2284`

Двойной клик по фону → `confirm()`, затем один-два `alert()`. Минусы: блокировка main thread, нулевая стилизация, плохая работа с AT, а на touch-устройствах двойной тап — штатный жест масштабирования, так что пасхалка будет срабатывать против воли пользователя (обработчик `dblclick` на `document`, 2257). В проекте уже есть удачный паттерн — ненавязчивый тост `.simpsons-toast` (2456–2460): его и стоит переиспользовать.

### J3. Конфликт таймеров перекраски matrix rain
`index.html:2272–2281` (Red Pill, возврат зелёного через 5000 мс) · `2453–2483` (Simpsons, сброс через 12000 мс)

Оба режима пишут в общую переменную `matrixColor` и оба планируют возврат к зелёному через `setTimeout` без отмены чужого таймера. Последовательность «двойной клик (красный) → набрать doh (жёлтый)» приводит к тому, что через 5 с жёлтый режим сбрасывается в зелёный, хотя до конца Simpsons-режима ещё 7 с: `simpsonsMode === true`, а цвет уже зелёный. Нужен один `setColorState(mode)` с отменой предыдущего таймера и приоритетом режимов.

### J4. Glitch-эффект работает вечно и форсирует reflow
`index.html:2347–2353`

```js
setInterval(() => {
    heroTitle.style.animation = 'none';
    void heroTitle.offsetWidth; // reflow для перезапуска
    heroTitle.style.animation = 'glitch 0.9s steps(2, end), glow-pulse 2s ease-in-out infinite 0.9s';
}, 6000);
```

Интервал не привязан к видимости `.hero` и к `document.hidden`: когда пользователь доскроллил до контактов, каждые 6 с выполняется readback `offsetWidth` (принудительный layout) и перезапуск анимации невидимого заголовка. Аналогично бессрочный генератор частиц (2428–2434) создаёт DOM-узел каждые 1.2 с — он хотя бы проверяет `document.hidden`. Обернуть оба в `IntersectionObserver` на `.hero`/условие видимости.

### J5. Parallax пишет inline-стили на каждый `mousemove` без троттлинга
`index.html:2356–2366`

Обработчик висит на всём `document` (действует и на скролле портфолио/контактов) и на каждое событие меняет `transform` двух слоёв, включая `canvas` с `scale(1.03)` — трансформация полноэкранного canvas заставляет композитор перерисовывать всю область дождя. Нужно: применять значения внутри `requestAnimationFrame` с кэшем, ограничить зоной `.hero`, отключать при `(pointer: coarse)`.

### J6. `innerHTML` при переносе технологий в модалку
`index.html:1931, 1946, 1929`

```js
const tech = this.querySelector('.project-tech').innerHTML;
openModal(title, description, `<strong>Технологии:</strong><div ...>${tech}</div>`);
// ... modalTechStack.innerHTML = tech;
```

Сейчас источник — собственный статичный HTML, XSS невозможен. Но паттерн опасен при переходе на динамические данные (CMS/API), а `modalTechStack` перезаписывается без экранирования. Рекомендация: `cloneNode(true)` узла `.project-tech` и `appendChild` вместо сборки строки.

### J7. При отключённом JS статистика показывает нули
`index.html:1418–1431` · JS `2050–2075`

Все четыре `.stat-number` содержат `0`; реальные значения лежат только в `data-target` и проставляются счётчиком. Без JS (или при медленном соединении) посетитель видит «0 проектов выполнено, 0 лет опыта». Положить честные значения в HTML, а анимацию начинать с 0 только если JS активен.

### P1. Render-blocking Google Fonts + метрический mismatch fallback'а
`index.html:9–10` · CSS `53`, `1783`

`<link rel="stylesheet">` на fonts.googleapis.com блокирует первую отрисовку; `display=swap` снимает невидимость текста, но даёт FOUT/CLS, потому что fallback `'Courier New', monospace` и `font-size = 16` в canvas-дожде (1783) используют другие метрики, чем Courier Prime/Roboto Mono. Варианты: self-host woff2 (~40 КБ, тот же origin, без внешнего запроса) либо `@font-face` с `size-adjust`/`ascent-override` для fallback.

### P2. Нет `canonical`, `robots.txt`, `sitemap.xml`
`index.html:5–6` · содержимое репозитория

Для GitHub Pages `/` и `/index.html` — два разных URL с одинаковым контентом → дубли в индексе. В репозитории отсутствуют `robots.txt` и `sitemap.xml`, в `<head>` нет `<link rel="canonical">`. Добавить canonical на канонический домен и минимальный robots/sitemap перед публикацией.

### P3. Canvas не учитывает `devicePixelRatio`
`index.html:1765–1766, 1820–1821`

`canvas.width = window.innerWidth` при DPR=2–3 даёт мыльные символы на retina/мобильных. Исправляется `canvas.width = innerWidth * dpr; ctx.scale(dpr, dpr)`. Плюс `drops.length = newColumns` (1828) при уменьшении окна теряет позиции столбцов — дождь «телепортируется» на каждом resize.

### C1. Демо-контакты + реальный `mailto:` получатель
`index.html:1712–1716` · `1894`

Телефон `+7 (999) 123-45-67` помечен плашкой «// Демонстрационные контакты», но форма отправляет на `hello@nexuscode.dev` как на настоящий адрес. Если домена нет — письма уходят в никуда, и пользователь не получит об этом никакой обратной связи (браузер просто откроет почтовый клиент). Перед публикацией нужен реальный адрес или серверный эндпоинт (Formspree/GitHub Issues/свой POST).

### S1. Год в футере захардкожен
`index.html:1743` — `&copy; 2026 NEXUS_CODE`. Через год станет неверным; ставить `new Date().getFullYear()` при загрузке.

## 🟡 Мелочи

1. `index.html:1369` — `tabindex="0" role="button"` на логотипе: подсказка про тройной клик спрятана в `aria-label`, из-за чего доступное имя перегружено; лучше короткое имя + `aria-describedby`.
2. `index.html:1372–1374` — `aria-label="Меню навигации"` дублирует содержимое `<span class="sr-only">Меню</span>` внутри той же кнопки. Оставить одно.
3. `index.html:1404–1405` — `НАЧАТЬ ПРОЕКТ` / `УЗНАТЬ БОЛЬШЕ` — `<button>` без указания пункта назначения; добавить `aria-describedby` («перейти к форме контактов» / «к разделу о компании»), иначе различие между ними для AT только в тексте.
4. `index.html:1443–1446` — эмодзи `✨ ⚡ 🔒 🔄` в `.feature-item` читаются как «искра», «высокое напряжение», «замок», «против часовой стрелки» — шум без смысла. Обернуть в `<span aria-hidden="true">`.
5. `index.html:1494, 1506, 1518, 1530, 1542, 1554` — `role="img" aria-label="..."` на `.project-image`, но сам эмодзи остаётся текстовым содержимым → дубль озвучивания. Добавить `aria-hidden="true"` на эмодзи-контент (или оставить `role="img"`, разбив label и содержимое).
6. `index.html:1669` — inline-`style` на `h3` (`text-align/margin-top/font-size`) против заявленного перехода на классы (`FIX audit #15`, комментарий 1176).
7. `index.html:1627–1665` — пять раз повторяются `aria-valuemin="0" aria-valuemax="100"`; блок проще генерировать из массива данных.
8. `index.html:1797` — `matchMedia('(prefers-reduced-motion: reduce)').matches` читается один раз и не подписан на `change`: пользователь, включивший «меньше движения» в середине сессии, продолжит видеть анимации.
9. `index.html:1848` — регулярка email принимает `a@b.c` и не покрывает IDN/кавычки; достаточно для UX, но не заменяет серверную проверку.
10. `index.html:1890–1895` — `window.location.href = mailtoLink` сразу после установки `formStatus.textContent`: статус может не успеть отрисоваться до ухода в почтовый клиент.
11. `index.html:1920` — `const modalContent = modal.querySelector('.modal-content')` не используется (мёртвый код).
12. `index.html:2133` — сравнение `konamiCode.join('')` без разделителей: последовательность склеивается в строку, что делает её чувствительной к составу ключей; читаемое `every`-сравнение массивов надёжнее.
13. `index.html:2520` — приветственный `console.log` перечисляет все пасхалки, включая «Type "doh"»: любой, кто откроет DevTools, получает готовый список. Если задумка в поиске — вывод стоит убрать.
14. `index.html:2311` — суффикс `+` добавляется ко всем целым счётчикам, включая «Лет опыта» (8+) и «Клиентов» (100+); для «лет опыта» `+` спортив стилистически.

## ✅ Что сделано хорошо

- Корневые атрибуты: `lang="ru"`, `charset="UTF-8"`, `viewport` **без** `user-scalable=no` (зум не заблокирован).
- Полный набор метаданных: description, OG (`type/site_name/title/description/locale`), Twitter Card, `theme-color`, favicon через data-URI без лишнего HTTP-запроса.
- `preconnect` к обоим шрифтовым хостам, `crossorigin` на gstatic, `display=swap`.
- Семантика: `header/nav/main/section/footer`, ровно один `h1`, `ul/li` в стеке технологий и в списках тарифов, `aria-labelledby="tech-stack-title"` у `ul.tech-stack` (1670).
- Форма: `novalidate` + собственная инлайн-валидация, `aria-required`, `aria-invalid`, `role="alert"` на контейнерах ошибок, `role="status" aria-live="polite"` на статусе, `autocomplete="name"/"email"`, фокус на первое невалидное поле (1887–1889).
- Модалка: `role="dialog"`, `aria-modal="true"`, `aria-labelledby="modalTitle"`, возврат фокуса на инициатора (1943–1947), Esc, клик по оверлею, `aria-hidden` в закрытом состоянии.
- Matrix rain: `requestAnimationFrame` с ограничением ~30 fps, пауза при `document.hidden`, полный стоп при `prefers-reduced-motion`, debounce resize 150 мс.
- `@media (prefers-reduced-motion: reduce)` глушит все анимации/переходы и прячет canvas (1265–1279).
- `.sr-only` вместо `display:none` для служебных текстов (85–95).
- Прогресс-состояние кнопки expressed через `aria-expanded`, синхронизируемое при клике по ссылке.
- Честные плашки «// Демонстрационные данные» над статистикой (1412), портфолио (1490), тарифами (1570) и контактами (1692).
- Контрастная схема: `#00FF41` на `#000` — контраст выше 12:1; scanline-оверлей с `pointer-events: none`.
