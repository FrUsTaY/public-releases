## 🔴 Критические баги (сломанная функциональность)

### 1. ✅ Счётчик статистики «Рейтинг 5.0» никогда не завершается
**Место:** JS, `statsObserver` (~строка 1940)
**Проблема:** Для дробного значения (`data-target="5.0"`) условие завершения `start >= target * 10` требует дойти до 50, но `stepTime = floor(2000/50) = 40 мс`, а счётчик инкрементируется на 1 каждые 40 мс — формально дойдёт, НО финальное значение записывается как `targetStr + '+'` → «5.0+» вместо «5.0», и при этом для «Клиентов 100» тоже пишется «100+». Кроме того, при быстрой прокрутке интервалы могут наслоиться. Главное: рейтинг отображается как «5.0+», что выглядит как ошибка данных.

**Решение:** учёт `isDecimal` при записи финального значения — рейтинг теперь показывает «5.0» без «+». Коммит: FIX audit #1.

### 2. ✅ Мобильное меню недоступно на планшетах (481–768px)
**Место:** CSS `@media (max-width: 480px)` (~строки 1085–1115)
**Проблема:** `.nav-links { display: none; }` и кнопка-бургер `.mobile-menu-btn { display: block; }` включаются только при ширине ≤480px. В диапазоне 481–768px навигация скрыта из-за первого правила `display:none` внутри media 768px?? Фактически в `@media (max-width: 768px)` `.nav-links` остаётся видимой, но сжата; при ≤480px скрывается. Между 481–768px пункты меню накладываются/не влезают. Брейкпоинт скрытия меню должен совпадать с брейкпоинтом появления бургера и быть не ниже 768px.

**Решение:** брейкпоинт меню перенесён в `@media (max-width: 768px)` — бургер и скрытая навигация включаются на одной ширине; дублирующиеся правила удалены. FIX audit #2.

### 3. ✅ Класс `.visible` от IntersectionObserver нигде не используется
**Место:** JS (~строка 1660) + CSS
**Проблема:** Скрипт добавляет skill-элементам класс `visible` при скролле, но в CSS нет ни одного правила `.skill-item.visible` / `.visible`. Анимация появления навыков фактически мертва — полосы навыков всегда имеют полную ширину из inline-стилей. Наблюдатель работает впустую.

**Решение:** полосы навыков анимируются через `transform: scaleX()` и правило `.skill-item.visible .skill-fill { transform: scaleX(1); }` — IntersectionObserver больше не работает впустую. FIX audit #3.

### 4. ✅ Форма использует `mailto:` — сообщения реально не отправляются
**Место:** HTML `<form action="mailto:...">` + JS-обработчик
**Проблема:** Отправка через локальный почтовый клиент ненадёжна (часто не настроен), пользователь получает два всплывающих окна (`confirm` + `alert`) и ничего не происходит. Нет сообщений об ошибке в самих полях (валидация только через `alert`). Это делает главную конверсионную форму неработающей.

**Решение:** убраны `alert/confirm/mailto action`; добавлена инлайн-валидация полей с сообщениями под каждым полем (`role="alert"`, `aria-invalid`, класс `.invalid`), статус-сообщение с прямым email-фолбэком. FIX audit #4. Полноценный бэкенд отправки — за рамками статичного лендинга (рекомендация).

### 5. ✅ Дублирование обработчика закрытия модалки по Escape конфликтует с пасхалками
**Место:** JS, глобальный `keydown` Escape + Konami-обработчик
**Проблема:** `closeModal()` вызывается даже когда модалка закрыта — безвредно, но буфер `konamiCode` засоряется служебными клавишами; при активном модальном окне нет ловушки фокуса (Tab уходит за пределы диалога), несмотря на `aria-modal="true"`.

**Решение:** обработчик Escape выполняется только при открытой модалке (`isModalOpen`), Konami-буфер больше не засоряется. FIX audit #5.

## 🟠 Проблемы доступности (a11y)

### 6. ✅ Кнопки хедера/CTA без якорной привязки
**Место:** HTML header (~строка 1120)
**Проблема:** `<button class="cta-btn">КОНСУЛЬТАЦИЯ</button>` не имеет ни обработчика, ни `aria-label` — кнопка в шапке полностью нефункциональна (клик ничего не делает).

**Решение:** кнопка КОНСУЛЬТАЦИЯ получила `id="headerCtaBtn"`, `aria-label` и обработчик скролла к форме контактов. FIX audit #6.

### 7. ✅ Не-семантические интерактивные элементы
**Место:** `.project-card` (div с role="button"), `.tech-item` (div), `.service-card` (cursor:pointer без действия)
**Проблема:** Карточки услуг имеют `cursor: pointer`, но кликабельны только внутренние кнопки — ложный сигнал интерактивности. Логотип — `div` с `cursor:pointer` (пасхалка), недоступен с клавиатуры.

**Решение:** у `.service-card` убран ложный `cursor:pointer`; логотип получил `tabindex="0"`, `role="button"`, `aria-label`, стили `:focus-visible` и обработку Enter/Пробел. FIX audit #7.

### 8. ✅ Нет `prefers-reduced-motion`
**Место:** CSS
**Проблема:** Бесконечные анимации (glow-pulse, blink, matrix rain, flicker) могут вызывать дискомфорт у пользователей с вестибулярными нарушениями. Рекомендуемое `@media (prefers-reduced-motion: reduce)` отсутствует.

**Решение:** добавлен `@media (prefers-reduced-motion: reduce)` — анимации/переходы гасятся, matrix rain полностью останавливается (CSS + JS-проверка `matchMedia`).

### 9. ✅ Модальное окно: нет ловушки фокуса и `aria-hidden`
**Место:** HTML modal + JS
**Проблема:** При открытом диалоге фокус может уйти на элементы страницы позади; закрытая модалка остаётся в дереве доступности (реализуется через `visibility:hidden` + `inert`).

**Решение:** реализована ловушка фокуса (цикл Tab/Shift+Tab внутри диалога) + управление `aria-hidden` на модалке (снимается при открытии, возвращается при закрытии). FIX audit #5/#9.

### 10. ✅ `outline: none` на фокусе формы без полноценной замены
**Место:** CSS `.form-group input:focus`
**Проблема:** Стандартный фокус-индикатор удалён, заменён только свечением `box-shadow`, которое слабо заметно на чёрном фоне для части пользователей. Нужна явная рамка/underline.

**Решение:** вместо `outline:none` — явный `outline: 2px solid var(--bright-green)` на фокусе полей. FIX audit #10.

## 🟡 SEO и мета-данные

### 11. ✅ Нет Open Graph / Twitter Card тегов
**Место:** `<head>`
**Проблема:** При шаринге в соцсетях нет описания/картинки. Также нет `canonical`, `og:title`, `theme-color`.

**Решение:** добавлены `theme-color`, Open Graph (`og:type/title/description/site_name/locale`) и Twitter Card мета-теги. FIX audit #11. (`canonical` опущен — нет боевого домена.)

### 12. ✅ Шрифты Google Fonts грузятся без preconnect и display swap fallback
**Место:** `<link href="https://fonts.googleapis.com/...">`
**Проблема:** Отсутствует `rel="preconnect"` к fonts.googleapis.com / fonts.gstatic.com — лишние задержки DNS/TLS при первой загрузке.

**Решение:** добавлены `<link rel="preconnect">` к fonts.googleapis.com и fonts.gstatic.com. FIX audit #12.

## 🔵 Производительность и код-стайл

### 13. ✅ Matrix rain работает даже когда вкладка не видна / не нужен после ухода секции
**Место:** JS `setInterval(drawMatrixRain, 33)`
**Проблема:** `setInterval` на 30fps жрёт CPU постоянно. Браузер притормаживает таймеры в фоновых вкладках, но canvas-перерисование всё равно избыточно. Лучше `requestAnimationFrame` + остановка при `document.hidden`.

**Решение:** matrix rain переведён на `requestAnimationFrame` с ограничением ~30fps и паузой при `document.hidden`. FIX audit #13.

### 14. ✅ Обработчик `resize` без debounce
**Место:** JS `window.addEventListener('resize', resizeCanvas)`
**Проблема:** Пересоздание canvas на каждое событие resize — дёргание и нагрузка на мобильных (частые resize при скролле адресной строки).

**Решение:** обработчик `resize` обёрнут в debounce (150 мс). FIX audit #14.

### 15. ✅ Инлайн-стили повторяются в разметке
**Место:** блоки `.demo-warning` (4 раза одинаковый `style="..."`), подписи цен, h2 модалки
**Проблема:** Дублирование стилей в HTML вместо классов — хуже поддерживаемость.

**Решение:** повторяющиеся инлайн-стили вынесены в классы `.demo-warning`, `.price-note`, `.price-note-highlight`, `.modal-title`, `.modal-description`. FIX audit #15.

### 16. ✅ `role="list"` / `role="listitem"` на div-обёртках
**Место:** HTML skills section
**Проблема:** Вместо семантического `<ul>/<li>` использованы div с ролями — рабочая, но избыточная a11y-костыльная конструкция (часть скринридеров в Safari игнорирует list-роли на div).

**Решение:** tech-stack переписан на семантические `<ul>/<li>`, role-костыли удалены; для `.tech-stack` задан `list-style: none`. FIX audit #16.

### 17. ✅ Нет favicon
**Место:** `<head>`
**Проблема:** Браузер запрашивает `/favicon.ico` → 404 в консоли и сети.

**Решение:** добавлен SVG-favicon через data-URI — запрос `/favicon.ico` больше не даёт 404. FIX audit #17.

### 18. ➖ JS-обработчики навешиваются без проверки существования элементов
**Место:** `document.getElementById('contactForm').addEventListener(...)`
**Проблема:** Если форма будет удалена/переименована — весь скрипт упадёт с TypeError (в отличие от остальных мест, где есть проверки `if (el)`).

**При проверке не подтверждён:** обработчик формы уже обёрнут в проверку `if (contactForm)`, все getElementById в коде защищены `if (el)`. Кодостайл-замечание снято без изменений.
