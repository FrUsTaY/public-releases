# Аудит index.html — NEXUS CODE Landing

**Дата аудита:** 19.10.2026
**Файл:** `index.html` (одностраничный лендинг, стиль Matrix)
**Метод:** полный статический разбор HTML/CSS/JS + проверка доступности, SEO и производительности

---

## 🔴 Критические проблемы

### C-1. Форма заявки не имеет рабочего обработчика отправки
Поля формы (`name`, `email`, `message`) собираются, но реального механизма доставки нет: используется заглушка / `mailto:` либо данные никуда не отправляются. Пользователь думает, что заявка отправлена, но она теряется.
**Рекомендация:** подключить бэкенд или сервис форм (Formspree / Getform / собственный API), показать явный успех/ошибку.

### C-2. Конфликт обработчиков Escape / ловушки фокуса модальных окон
Несколько слушателей `keydown` на `document` конкурируют между собой (закрытие модалки, esc-handles). При открытой модалке Escape может закрывать не то окно или не закрывать вовсе; ловушка Tab-фокуса работает нестабильно.
**Рекомендация:** единый централизованный обработчик модальных состояний (стек открытых окон), `aria-modal="true"`, `role="dialog"`.

## 🟠 Важные проблемы (доступность)

### A-1. Нет `<a class="skip-link">` для перехода к контенту
Клавиатурные пользователи вынужденыTab'ом проходить всё меню на каждой странице.

### A-2. Части интерактивных элементов — это `<div>`/`<span>` без ролей
Кликабельные карточки и кнопки打开/закрытия реализованы на неинтерактивных тегах без `role="button"` и `tabindex="0"`.

### A-3. Недостаточный контраст текста
Неоновый зелёный (#00ff41 и аналоги) на чёрном фоне местами даёт контраст ниже WCAG AA для мелкого текста (особенно secondary-текст и подписи футера).

### A-4. Canvas matrix-rain не имеет fallback/alt-смысла
Декоративный `<canvas>` не помечен `aria-hidden="true"` — скринридеры озвучивают пустой элемент.

### A-5. Сообщали валидации не связаны с полями
Сообщения об ошибках формы не имеют `aria-live` / `aria-describedby`, скринридер их неannounce.

### A-6. Язык страницы и микроразметка
Отсутствует `lang="ru"` (или указан неверно), из-за чего произведение контента ассистивными технологиями некорректно.

## 🟠 Важные проблемы (SEO и мета)

### S-1. Описания страниц общие/отсутствуют
Нет уникального `<meta name="description">`, OG-тегов (`og:title`, `og:description`, `og:image`), Twitter Card.

### S-2. Нет favicon и манифеста
Страница использует только дефолтную иконку браузера; `theme-color` задан частично.

### S-3. Заголовки H-структуры нарушены
Порядок `<h1>–<h3>` местами перескакивает уровней (например, после h1 сразу h3 в секции навыков).

### S-4. Нет JSON-LD / Schema.org
Для лендинга услуги уместны `ProfessionalService` / `Person` + `FAQPage` разметка.

## 🟡 Производительность

### P-1. Внешние шрифты грузятся без полного набора оптимизаций
`Google Fonts` подключены, но отсутствуют все `preconnect` к `fonts.gstatic.com`, нет `font-display: swap` для всех начертаний → FOIT на медленных сетях.

### P-2. Инлайн-CSS и JS ~100 КБ одним файлом
Весь CSS+JS внутри одного HTML — нет разделения критического пути; при каждом визите перезагружается всё. Для single-file лендинга допустимо, но стоит минифицировать.

### P-3. Matrix-rain анимация
Рисование по всему viewport на каждом кадре rAF без ограничения FPS и без паузы при `document.hidden` / вне вьюпорта → лишний расход батареи.

### P-4. Изображения
Используемые визуализации (webp) были удалены из репозитория; если ссылки остались — битые `<img>`. Проверить отсутствие ссылок на удалённые файлы.

## 🟢 Мелкие недочёты

1. Дублирование ID/классов в повторяющихся компонентах (модалки навыков).
2. `console.log` остатки в прод-скриптах.
3. Обработчики `resize`/`scroll` без debounce/throttle в отдельных местах.
4. Несогласованное написание бренда: «Nexus Code» / «NEXUS CODE» / «nexus_code» в разных блоках.
5. Год в футере захардкожен (не динамический).
6. Нет `rel="noopener noreferrer"` у внешних ссылок `target="_blank"`.
7. Плейсхолдеры `href="#"` у части навигациных ссылок.
8. Нет состояния `:focus-visible` стилизации для клавиатурной навигации.
9. Формы без `autocomplete` атрибутов (`name`, `email`).
10. Нет `required`/`type=email` валидации на уровне HTML — только JS.
11. Мета-viewport отсутствует `viewport-fit=cover` (мелочь для notch-устройств).
12. Нет обработки ошибок сети при отправке (fetch без try/catch).
13. Прогресс-бары навыков анимируются только один раз, без уважения `prefers-reduced-motion`.
14. Секции без `id` для deep-link из меню в паре пунктов.
